# Harness Protocol v1 research questions for Milestone 2

- Does the schema preserve enough plugin source/version/integrity detail for AutoDev provenance?
- How are permissions scoped and merged, and can AutoDev map them losslessly to requested capabilities?
- What governance fields can narrow AutoDev behavior without conflicting with kernel policy?
- How are plugin dependencies/version ranges resolved by the reference implementation?
- What MCP lifecycle/configuration semantics need Android/remote-companion adaptation?
- How are sensitive environment requirements represented without persisting values?
- Which AutoDev asset kinds (Evaluator, ContextProvider, Workflow, AgentProfile) require extensions or composition rather than direct fields?
- What extension/namespacing mechanism best preserves round-trip compatibility?
