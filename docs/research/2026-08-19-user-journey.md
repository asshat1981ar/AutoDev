# Target Android-first user journey

1. User opens AutoDev and selects/imports a repository.
2. Environment diagnostics explain what is locally available and what requires a remote companion.
3. User describes an objective in ordinary language.
4. AutoDev presents a concise durable plan: outcome, milestones, likely risk/capability needs, and verification target.
5. Run begins; the primary screen shows current milestone, verified progress, blockers, and required intervention.
6. When an effect needs approval, AutoDev shows the exact operation/capability scope and relevant diff/context.
7. Network/process loss transitions the run into durable offline/interrupted state rather than losing work.
8. On resume, uncertain effects are reconciled before continuation.
9. Completion shows produced changes plus independent build/test/static/security evidence and remaining limitations.
10. The same run can be inspected/resumed from supported companion platforms without changing authority semantics.
