# Harness UX direction

Users should see the active harness as a comprehensible configuration, not a wall of MCP/tool names. Group assets by role (agents, skills, tools/MCP, workflows/hooks, evaluators/context), show provenance/trust/requested capabilities, and explain why each is active for the run.

Advanced users can inspect exact manifests/configuration. Changes create explicit profile/config revisions and may require revalidation before an active run adopts them.
