# First-run/onboarding direction

A production AutoDev first run should progressively diagnose rather than demand a large configuration form.

1. Detect platform and available local capabilities.
2. Select/import repository.
3. Explain which execution modes are available locally versus through a companion/server.
4. Validate ForgeCore/control-plane connectivity and repository access.
5. Discover optional harness assets without activating effectful permissions.
6. Offer a small safe objective that demonstrates plan -> execution -> evidence.
7. Persist diagnostics so recurring environmental failures are actionable.

Android/Termux onboarding must avoid desktop-only assumptions.
