# Android accessibility direction

Primary run states must be understandable without relying on color alone. Approval, failure, interrupted, verified, and blocked states need concise text labels and accessible semantics. Diff/evidence views should support readable typography, focus order, screen-reader descriptions, and expandable detail rather than dense fixed dashboards.

Accessibility verification belongs in release qualification, but component semantics should be designed during Android Workspace implementation rather than retrofitted at the end.
