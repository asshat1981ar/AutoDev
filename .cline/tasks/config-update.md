# Task: Configuration Update

**ID**: config-update
**Type**: Maintenance
**Priority**: Varies (High for security, Medium for versions, Low for formatting)
**Estimated Duration**: 15-45 minutes depending on scope
**Required Agents**: Config Manager, Builder

## Objective

Update one or more configuration files in a controlled, validated manner that respects AutoDev's harness rules and trust boundaries.

## Prerequisites

- Configuration audit (`config-audit`) has been run recently
- Changes are documented in an issue or ADR (for significant changes)
- Local development environment is set up

## Inputs

Required inputs (provide when starting this task):
- `component`: Which component's configuration to update (rust, kotlin, python, ci, security, defaults)
- `file`: Specific configuration file(s) to update
- `change`: Description of the change
- `reason`: Why this change is needed (issue reference, ADR, etc.)
- `priority`: Priority level (high, medium, low)

Optional inputs:
- `version`: New version if updating tool versions
- `test`: Whether to run integration tests (true/false, default: true)

## Steps

### Step 1: Validate Current State

**Agent**: Config Manager
**Action**: Ensure we start from a clean state

```bash
cd /path/to/AutoDev

# Check current state
git status
git diff

# Run validation
python config/validate.py

# Run drift check
python scripts/check_harness_drift.py
```

**Acceptance Criteria**:
- [ ] Current state is clean or only expected changes are present
- [ ] Validation passes with 0 errors
- [ ] Drift check passes

### Step 2: Identify Impacted Files

**Agent**: Config Manager
**Action**: Determine all files that need to be updated

**Command**:
```bash
# Find all files that might be affected
grep -r "[old-value]" config/ AGENTS.md .github/workflows/ci.yml --include="*.toml" --include="*.yaml" --include="*.yml" --include="*.properties" --include="*.json" --include="*.md"
```

**Template**:
```
Impacted Files:
1. config/[component]/[file] - Primary change
2. [file2] - Secondary change if needed
3. [file3] - Documentation update if needed
```

### Step 3: Make Changes

**Agent**: Builder
**Action**: Apply the configuration changes

**Guidelines**:
- Update only the specified files
- Maintain consistent formatting (2 spaces, 100 char width)
- Update comments to explain the change
- Add version pin changes to changelog if applicable

**Example**: Updating Kotlin version
```bash
# Edit config/kotlin/gradle.properties
# Change: kotlin.version=2.0.21 -> kotlin.version=2.0.22

# Update AGENTS.md if the version is mentioned there
# Update .github/workflows/ci.yml if needed
```

**Acceptance Criteria**:
- [ ] Changes are minimal and focused
- [ ] Formatting is consistent
- [ ] Comments are updated

### Step 4: Validate Changes

**Agent**: Config Manager
**Action**: Run all validation checks

```bash
# Syntax validation
python config/validate.py

# Harness consistency
python scripts/check_harness_drift.py

# Specific validations based on component
case $component in
  rust)
    cd crates && cargo check && cd ..
    ;;
  kotlin)
    cd kotlin && ./gradlew --dry-run && cd ..
    ;;
  python)
    python -m py_compile config/python/*.ini
    ;;
esac
```

**Acceptance Criteria**:
- [ ] `config/validate.py` reports 0 errors
- [ ] `check_harness_drift.py` passes
- [ ] Component-specific validation passes

### Step 5: Run Integration Tests (if test=true)

**Agent**: Verifier
**Action**: Verify the change doesn't break anything

**Rust**:
```bash
cd crates
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cd ..
```

**Kotlin**:
```bash
cd kotlin
./gradlew ktlintCheck --no-daemon
./gradlew :mpp-core:assemble --no-daemon
cd ..
```

**Python**:
```bash
python -m py_compile scripts/*.py .cline/hooks/*.py
python -m unittest discover -s tests -v
```

**CI**:
```bash
# Just validate the workflow syntax
yaml-lint .github/workflows/ci.yml 2>/dev/null || true
```

**Acceptance Criteria**:
- [ ] All format checks pass
- [ ] All lint checks pass
- [ ] All compilation checks pass

### Step 6: Create Commit

**Agent**: Builder
**Action**: Commit the changes with proper message

**Commit Message Template**:
```
[prefix](config): [brief description]

[Optional body with details]

[Optional footer with issue references]

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
```

**Prefix Guidelines**:
- `feat(config)`: New configuration feature or major version bump
- `fix(config)`: Bug fix in configuration
- `chore(config)`: Routine maintenance (minor version bumps, formatting)
- `docs(config)`: Documentation-only changes
- `refactor(config)`: Structural changes without functional impact

**Command**:
```bash
git add [changed-files]
git commit -m "[prefix](config): [description]"
```

### Step 7: Verify and Document

**Agent**: Config Manager
**Action**: Ensure the change is properly documented

**Checklist**:
- [ ] Change is documented in `config/README.md` if significant
- [ ] Version changes are documented in appropriate files
- [ ] Any new configuration is documented

**Documentation Update Template**:
```markdown
## [Date] - [Change Description]

**Files Changed**:
- `config/[component]/[file]` - [What changed]

**Reason**: [Why the change was needed]

**Impact**: [What this affects]

**Related**: [Issue number, ADR, or other reference]
```

## Success Criteria

All of the following must be true:
1. ✅ Changes are focused and minimal
2. ✅ Configuration validator reports 0 errors
3. ✅ Harness drift check passes
4. ✅ Component-specific validation passes
5. ✅ Integration tests pass (if test=true)
6. ✅ Commit message follows conventions
7. ✅ Documentation is updated

## Rollback Procedure

If the change causes issues:

```bash
# Identify the commit
git log --oneline -5

# Revert the commit
git revert [commit-hash]

# Or reset to previous state (use with caution)
git reset --hard HEAD~1
```

## Examples

### Example 1: Update Kotlin Version

**Input**:
```
component: kotlin
file: config/kotlin/gradle.properties
change: Update Kotlin version from 2.0.21 to 2.0.22
reason: Security update in Kotlin 2.0.22
priority: high
version: 2.0.22
test: true
```

**Steps**:
1. Update `config/kotlin/gradle.properties`
2. Update `AGENTS.md` if needed
3. Update `.github/workflows/ci.yml` if needed
4. Run validation
5. Test Kotlin build
6. Commit with message: `chore(config): Update Kotlin to 2.0.22`

### Example 2: Update Rustfmt Configuration

**Input**:
```
component: rust
file: config/defaults/rustfmt.toml
change: Change max_width from 100 to 120
reason: Better compatibility with existing code
priority: low
```

**Steps**:
1. Update `config/defaults/rustfmt.toml`
2. Run validation
3. Run `cargo fmt --all -- --check`
4. Commit with message: `chore(config): Update rustfmt max_width to 120`

### Example 3: Add New Security Rule

**Input**:
```
component: security
file: config/security/ast-grep.yml
change: Add new rule for forbidden pattern
reason: Security hardening
priority: high
```

**Steps**:
1. Add rule to `config/security/ast-grep.yml`
2. Run validation
3. Run `ast-grep scan --config config/security/ast-grep.yml .`
4. Commit with message: `feat(config): Add security rule for pattern X`

## Automation

This task can be automated with a script:

```bash
#!/bin/bash
# config-update.sh

COMPONENT=$1
FILE=$2
CHANGE=$3
REASON=$4

# Validate
echo "Validating current state..."
python config/validate.py
python scripts/check_harness_drift.py

# Make changes (manual step)
echo "Please make your changes to: $FILE"
echo "Change: $CHANGE"
echo "Reason: $REASON"

# Post-change validation
echo "Validating changes..."
python config/validate.py
python scripts/check_harness_drift.py

echo "Configuration update complete!"
```
